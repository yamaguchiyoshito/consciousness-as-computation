# 編集・保守ガイド

[連載目次へ](../README.md)

## 原本と生成物の責務

| パス | 責務 | 編集方法 |
| --- | --- | --- |
| `chapters/*.md` | 各回の本文、図の参照とキャプション、前後リンク | 直接編集する |
| `series.json` | 回の順序、題名、副題、概要、部（`parts`）、各回の図の一覧（`figures`）、関連する連載へのリンク | 本文変更と同じPRで整合させる |
| `assets/illustrations/*.svg` | 本文から参照する独立した挿絵 | `draw_figures.py` を編集して再生成する |
| `scripts/draw_figures.py` | 表紙と各回の図（計64点）を再現する図形コード。`CHAPTERS` の登録順が枝番とファイル名を決める | 原則としてこちらを編集する |
| `claudedocs/figure-plan-2026-10-29.md` | 図版の配置と意図 | 図を増減したときに更新する |
| `site-src/styles.css` | HTML閲覧用の見た目 | 本文内容を持たせない |
| `scripts/build.py` | MarkdownをHTMLへ変換 | 原本を改変しない |
| `scripts/validate.py` | 本文・参照・SVGの構造検査 | 検査規則を保守する |
| `scripts/check_html.py` | HTMLの相対リンク・アンカー・外部依存を検査 | 生成後に実行する |
| `tests/` | 検査・変換の回帰試験 | 成功例と失敗例を両方持つ |
| `scripts/publish.py` | 新規GitHubリポジトリ作成の補助 | 既存リポジトリには使わない |
| `_site/` | ブラウザ用生成物 | 直接編集せず再生成する |

## 変更の最小手順

```sh
# Markdown や図の生成コードを編集した後
python scripts/draw_figures.py
python scripts/validate.py
python -m unittest discover -s tests -v
python scripts/build.py
python scripts/check_html.py
```

SVGを直接修正すると次の図再生成で上書きされる。長期保守する変更は `draw_figures.py` に反映する。

## 各回の型

各回の冒頭は `# 第N回　題名`、その直下に一行の主題を `## 副題` として置く。`series.json` の `title` と `subtitle` と一致していることを検査が確かめる。続けて `<!-- NAV:TOP -->` で囲んだ前後リンク、本文、`<!-- NAV:BOTTOM -->` で囲んだ前後リンクの順に並べる。末尾のナビには次回の題名がビルド時に添えられるので、本文に「次回：…」の行は置かない。

本文の節は `### 1. …` の番号付き見出しと `### おわりに：…` で構成する。節が多い回（第8回・第9回）は、節を3〜6のまとまりに分けて、まとまりの見出しを `###`、番号付き節を `####` に落とす。本連載の見方は第3回で「目的関数モデル」と名づけており、「本モデル」とは書かない。目的関数モデルが置いた仮説と、提唱者の理論の参照は、本文中で区別して書く。数式は本文中のコード表記（バッククォート）で示し、添字は `w_i` のように ASCII で書き、初出の式には「（式N-k）」と番号を付けて以降は番号で参照する。式の直後に日本語の読み下しを一文添える。数式レンダラーは使わない。段落は二〜四文を目安にまとめ、問いかけや核となる主張、例の列挙だけを一文段落にする。

## 図の置き方と密度

図は、その内容を説明し終えた段落の直後に置く。次の節の内容を先に見せる図は、該当する節へ移す。1枚につき主張は1つ、パネルは2枚まで、ラベル文は10個前後までとする。1回あたり4〜11枚、おおむね一節に一枚を目安とする。一節に二枚以上置くなら本文側の説明を疑う。

ファイル名は `NN-x-slug.svg`（回番号と枝番）で、`scripts/draw_figures.py` の `CHAPTERS` に登録した順に枝番が付く。`series.json` の `figures` には本文での登場順に並べる（`python scripts/draw_figures.py --list` で一覧を出せる）。Markdownから `![代替テキスト](../assets/illustrations/04-a-prediction-loop.svg)` のように相対参照し、直後に `*図N-k：前提の説明*` というキャプションを置く。`k` は回内の通し番号で、検査は `figures` の数と順序に一致することを確かめる。SVGコードを本文へ貼り付けない。

SVGには `viewBox`、`role="img"`、`title`、`desc` を持たせる。`script`、`foreignObject`、外部画像、外部フォント、イベントハンドラは入れない。グラデーションなど `url(#id)` による内部参照は許す。矢印や色だけに意味を依存させず、ラベルでも区別する。日本語の表示は閲覧環境のフォントを利用し、フォントファイルは同梱しない。

## 出典について

本連載は脚注による出典一覧を持たない。参照する理論は本文中で提唱者名とともに言及する。脚注を導入する場合は、`[^id]` 形式の脚注と末尾の `## 参考文献・注記` 節を使い、`series.json` の `sources` と `references/sources.json` を揃える。検査はその整合を確かめる。

## 公開前の目視確認

GitHubのPreview、HTMLのデスクトップ幅とスマートフォン幅で確認する。ページ全体の横はみ出し、欠けた日本語、切れた図の文字は修正する。
